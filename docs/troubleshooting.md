# 常见问题

先确认所选 preset、开发板芯片版本、显示/触摸型号和实际接线一致。排查期间不要
带电插拔 MIPI-DSI 或触摸 FFC。

## 找不到 `idf.py` 或提示 SDK 版本不匹配

请从 ESP-IDF 5.5.3 自带的终端进入仓库，并运行：

```sh
idf.py --version
```

当前 preset 固定使用 5.5.3。不要通过修改 preset 的版本号来绕过检查；不同 SDK
需要单独完成构建和实物验证。

## 不知道该选 r1 还是 r3

读取芯片版本：

```sh
esptool.py -p <PORT> chip_id
```

v1.x 使用 `waveshare-pico-r1-*`，v3.x 使用 `waveshare-pico-r3-*`。商品名相同
不代表芯片修订相同。

## 串口打不开或烧录失败

- 确认 `<PORT>` 已替换为实际串口。
- 关闭其他正在占用串口的软件。
- 确认 USB 线支持数据传输，并重新读取 `chip_id`。
- 确认烧录命令中的 App 路径和构建目录属于同一个 preset。

## 提示 `Recipe changed since sdkconfig was created`

这表示硬件配方改变后，旧 `sdkconfig` 不能安全复用。普通用户应重新克隆或使用
新的 preset；开发者可先把对应的 `out/<preset>/` 移到仓库外留档，再重新构建。
不要删除其他 preset 的输出，也不要修改生成文件绕过检查。

## 串口正常但屏幕黑屏、蓝屏或图像异常

1. 先确认使用的是对应芯片版本的 preset。
2. 完全断电后检查显示 FFC、转接板方向和供电，再重新上电。
3. 使用 `*-colorbar` preset 检查完整视频链路。
4. 对照[测试方法](testing.md)检查颜色、方向和边界。

面板 BIST、主控彩条和帧缓冲画面经过的链路不同，只有其中一个正常时不能直接
判定屏幕损坏。若每次只有重新插接才能显示，请停止重复插拔并提交完整硬件信息；
这通常需要检查复位、供电或启动时序。

## 能显示，但触摸没有反应

- 确认使用 `*-touch` preset 和 `touch-test` App。
- Waveshare ESP32-P4-Pico 当前接线为 GPIO8 SCL、GPIO7 SDA。
- 串口应能识别 GT9271，地址可能是 `0x5D` 或 `0x14`。
- 如果已识别但没有触点，记录触摸时的串口输出，不要先改显示时序。

摄像头等其他外设可能与触摸共用 I2C 引脚。遇到冲突时请在 Issue 中列出全部
接入设备和引脚。

## 如何提交可复现的问题

按[参与贡献](../CONTRIBUTING.md)中的问题模板提供硬件型号、版本、preset、SDK、
源码提交、日志和实物画面。说明已经尝试的步骤；同一问题不要反复更换多个时序、
初始化表和接线，否则很难判断是哪项改动产生影响。
